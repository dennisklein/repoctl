Delivery and verification

This chapter gives the order in which repoctl is built and the tests that must pass before the code depends on a fact. It also lists the assumptions of the design and the questions that are still open.

  • Eight phases, 0 to 7. Each phase ends with a "done when" in the terms of the data story.
  • Phase 0 puts the tool on branch main, with CI and this docs site on GitHub Pages.
  • The bash-era scripts stay on the builder branches until the first publish with repoctl.
  • Tests V1 to V29 run on Rocky 9, Rocky 10 and the Fedora host. Each test names the phase that it gates.
  • Each open question names the phase that needs the answer.

Assumptions

The design depends on these facts. A test or a human confirms each of them. When one is false, the chapter that it names must change.

  • The clients run Rocky 9 and Rocky 10 with the stock rpm, dnf and librepo of the c9s and c10s spec files. The facts F1 to F18 hold for these versions (client facts; V10 to V18).
  • Config management installs the release package on every client and on the HTTP server. A human can tell when the rollout is complete (onboarding).
  • The HTTP server can run a systemd timer and has curl, jq, gnupg2 and rpm (mirror job; V1).
  • The mirror job runs every 5 minutes. A shorter interval only adds HEAD requests. Clients read a new repomd.xml after metadata_expire (one hour).
  • GHCR has no tag compare-and-swap. publish compares latest in step 1 and in step 7. The window between the two is acceptable, because the team coordinates in its own channel (two admins).
  • The GHCR packages are public, so the mirror job pulls without a token. A push needs a classic token with write:packages and a team with write access (registry access; V2, V3).
  • rpmautospec raises the release for each commit, also for an empty one (rebuild; V19). For an in-tree package, V6 shows which commits count.
  • go-clikit gives the span id (Span.TraceContext()), the doctor format and the progress log. repoctl needs no change in go-clikit for the journal (journal).
  • The UI agent is Claude Code (agent: {command: claude}). repoctl reads its stream-json output (agent config).
  • mock exits with 30 when dnf builddep fails (V20).
  • Host names, the server path /srv/repos/slurm-repo, the GitHub team name, the fingerprints and the commits in the examples are placeholders. The data story fixes them for all chapters.
