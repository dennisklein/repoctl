repoctl: build state, rebuilds, snapshots, LLM in the UI

Date: 2026-11-02. Status: decided. This document changes parts of 02-repoctl.html and 04-cli-ui.html. Section 9 lists the changes.

1. Summary

  • The published repo is the build state. Each target repo carries a repoctl manifest in its signed repodata. The next build reads it. repoctl builds only nodes whose package commit is not in the manifest.
  • No automatic rebuild of dependents. A change in ucx does not rebuild slurm. repoctl trusts upstream ABI stability, as Dennis does today.
  • A rebuild is a commit. repoctl rebuild slurm --reason "…" makes an empty commit on the package branch. rpmautospec raises the release (Fedora mass rebuilds work the same way). Thus, every build has a new NVR. The same-NVR problem is gone by design.
  • Advisories say when a rebuild is necessary. They are deterministic checks: a removed soname, a broken repoclosure against the current upstream repos, a changed buildroot. They suggest; the person decides.
  • Keep all versions. Pruning is explicit, granular and closure-safe.
  • Snapshots go to an OCI registry as artifacts (one blob per file, not image layers). This gives content hashes, deduplication, rollback and a shared state for the team. It replaces the git repo of builds.
  • LLM in the UI: advisory buttons, no chat in v1. A button runs a local agent with a fixed skill and shows its result. Actions stay buttons that a person clicks.

2. D1: many keys, one signature per file

Two different things have the name "multiple":

  • Many trusted keys on the clients: yes, this works. The release RPM installs the public keys of all admins. dnf and rpm accept a file if its signer is one of these keys. This is verified on EL9 and EL10 (rpm and dnf source).
  • Many signatures on one file: do not use it. rpm 4.16 (EL9) keeps only one signature per RPM. EL10 can store more, but then it needs all signer keys. EL10 librepo refuses a repomd.xml.asc with more than one signature.

A node that an earlier, unpublished run built with the same commit and the same target config is reused from that run's staging (plan action staged). Thus, a failed run does not rebuild its good nodes.

The full buildroot list (mock installed_pkgs.log) is a separate file. It is the record of the upstream versions that a package was built against.

4. Advisories

Advisories are deterministic. repoctl computes them in plan, after each node build, and in repoctl check (also from a timer). The UI and the agent read the same list (Advisory kind in the contract).

CodeLevelWhenCheckSuggests
soname.removedrequiredafter a node buildA soname that the published version provides is gone in the new build, and another set package requires it.repoctl rebuild <dependents> --reason "ucx: libucp.so.0 → .so.1". Publish refuses unless the dependents are in the same run or the person overrides.
closure.brokenrequiredplan, checkdnf repoclosure per target: published repo + current upstream repos. A requirement of a published RPM has no provider any more (upstream removed or changed a soname).Rebuild the affected package.
abi.changedwarnafter a node build (optional, needs libabigail)abidiff of the shared libraries, old vs new, same soname.Review; maybe rebuild dependents.
buildroot.driftinfoplan, checkA BuildRequires provider in the upstream repos now has a newer version than in the recorded buildroot (e.g. hwloc-devel 2.4 → 2.11).Nothing, or a rebuild if the person wants the new features.
mock.driftinfoplanmock config or macros hash differs from the manifest.Nothing, or rebuild.
upstream.releaseinfoupstream, checkNew upstream version of the package itself (today's package-info).Bump the version (skill bump-package).

5. Keep all versions, prune on request

  • Publish adds to the repo. It never deletes. This is today's createrepo --update behaviour.
  • repoctl repo prune deletes only on request, with a dry run first (default). Selectors can be combined:
repoctl repo prune --target el9 --keep-last 3              # per package name
repoctl repo prune --repo debuginfo --keep-last 1          # debuginfo only
repoctl repo prune --older-than 2y --package openmpi
repoctl repo prune --nvr slurm-26.05.2-1.el9               # one build (all its subpackages)
repoctl repo prune … --apply                               # really do it

Safety rules: never delete the newest NVR of a package. Never delete an NVR that a kept package requires (repoclosure after the prune must pass). Prune makes a new snapshot; old snapshots still hold the files until snapshot retention deletes them.

6. Snapshot store: OCI

Today the builds are in a git repo. Git keeps every version of every binary in its history, so clones grow and you cannot delete one old file. I agree with OCI, with one change: use an OCI artifact with one blob per file, not an image with layers.

OptionContent hash, dedupPrune one NVRRestore a snapshotTeam sharingCost

Plain dir + rsync backupnoyesbackup restorefile sharelow, no history
Pulpyesyesyesserverhigh (server)
  • Commands: repoctl repo push (publish does it), repo pull [ref], repo snapshots, repo restore <ref> (rollback = publish an old snapshot to the mirror), repo gc --keep-snapshots ….
  • Registry: GHCR of this repo (decided). Config: store: {oci: ghcr.io/dennisklein/slurm-repo} in repoctl.yaml. One package per set and target, for example ghcr.io/dennisklein/slurm-repo/slurm-26.05-el9. The annotation org.opencontainers.image.source links each package to the repo. Credentials come from the user's container login (oras login ghcr.io with gh auth token or a token with write:packages), never from the config.
  • Two admins publish at the same time. Publish checks that …-latest still points to the snapshot that the build started from. If not, it stops and asks for repo pull and a new plan. Registries have no atomic tag compare-and-swap, so a small race window stays; the set lock convention covers it for a small team.
  • Size: one RPM is stored once in all snapshots of all targets that hold it. Debuginfo can go to its own repository path, with its own retention.
  • GHCR specifics. GHCR has no garbage collection that the user starts. repoctl repo gc deletes old package versions through the GitHub REST API (token scope delete:packages). GitHub frees the blobs that no version uses. Public packages are free; private packages count against the GitHub Packages storage quota. The debuginfo repos are the largest part.

10. Former open points (decided 2026-11-02)

  1. Snapshot registry: GHCR of this repo (section 6).
  2. soname.removed and closure.broken block publish. --accept-advisory <code> overrides with a reason, which goes into the journal. Only info and warn advisories can be dismissed.
  3. repoctl check runs from a systemd user timer (daily). It reports in the UI (badge and Advisories page) and in repoctl status. No mail in v1.
  4. LLM in the UI: advisory buttons, no chat in v1 (section 7).
