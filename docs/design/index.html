Design record

repoctl

Build signed RPM repositories from a package set.

repoctl is one Go binary with a CLI, a local web UI and an MCP server for agents, all on one core. It builds each package in a mock chroot with the rpmautospec plugin. It signs the RPMs with personal keys and publishes each repository as a snapshot in GHCR. repoctl runs on Fedora and builds for EL9 and EL10.

Key decisions

The thirteen decisions that shape the design. Each card links to the chapter that specifies it.

  1. One Go binary on go-clikit gives the CLI, the local web UI and the MCP server one core, and mock stays the build isolation.Why a Go tool
  2. Data on branches: the tool lives on main, each set/<set> branch holds one package set, and each package has its own branch.Where the tool lives
  3. The published repo is the build state: only new commits build, and a rebuild is an empty commit.Core model
  4. Advisories are deterministic checks that suggest a fix, and a human decides.Advisories
  5. GHCR is the authority: each snapshot is one OCI artifact, and a mirror job serves latest over HTTP.Publish and snapshots
  6. Publish has eight steps, and only step 7, the tag, changes what other humans see.Publish order
  7. Personal signing keys: the clients trust all team keys through the release package, with one signature per file.Signing and trust
  8. Supply chain records: each build has SLSA provenance and a CycloneDX SBOM in the snapshot, and the repository signature covers them.Supply chain records
  9. Shared state needs a human: each such command has a dry run, a summary, a confirmation and a journal, and no MCP tool.Safety rules
  10. Fedora hosts, EL targets: each admin builds as an own user or on an own host, without a build queue and without a lease.Humans and hosts
  11. The web UI is local to one user, and its agent buttons run a fixed skill with a read-only MCP server.Web UI
  12. Calm output: the UI and the terminal show exceptions first, one primary action, and red only for the blocker.Calm rules
  13. Import by runbook: an agent imports the bash-era repos with a runbook, not with an import command.Import runbook
