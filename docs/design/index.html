repoctl design record

repoctl builds signed RPM repositories from a package set. It calls git, mock with rpmautospec, rpmsign and createrepo_c. It has a CLI, a local web UI and an MCP server. These documents record the design decisions of 2026-11-02. Read them in order. A later document wins over an earlier one.

Main decisions

  • One Go binary, repoctl, on GSI-HPC/go-clikit. mock stays the build isolation.
  • The tool lives on the orphan branch main. Each builder/slurm-<version> branch is one package set (data only).
  • The published repo carries a manifest and is the input of the next build. Only new commits build. A rebuild is an empty commit (repoctl rebuild).
  • Advisories (soname, repoclosure, buildroot drift, upstream releases) suggest rebuilds. The person decides.
  • Personal signing keys. Clients trust all team keys. One signature per file.
  • Snapshots of each target repo go to ghcr.io/dennisklein/slurm-repo as OCI artifacts, one blob per file.
  • Agent skills ship with repoctl. Package facts live in repoctl.yaml. The web UI has advisory buttons that run a local agent, no chat.
