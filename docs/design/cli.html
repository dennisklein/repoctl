CLI reference

This chapter is the reference of the repoctl command line. It gives the command tree, the global flags, the selectors, the exit codes and one block for each command. It also gives the shared-state safety rules, the help topics, shell completion, the migration from the bash scripts and the error message style.

  • The CLI, the web UI and the MCP server use one core. The words, the selectors and the exit codes of this chapter apply to all three.
  • 47 command blocks in eight groups. Each command has one safety class: read, staging, local write or shared state.
  • Results go to stdout. Progress, notes, warnings, hints and errors go to stderr (output rules).
  • The exit codes 0 to 13 and 130 are a contract. repoctl can add a code, but it never renumbers a code.
  • A shared-state command has a dry run, a summary, a typed confirmation, the set lock, a journal and no MCP tool.
  • A failed command ends with one error line and 0 to 3 hints. The normal path ends with one Next: line.

Principles

  • Same words everywhere. A command name, a flag, a column header and a JSON field use the same word of the model (model.html#glossary).
  • Results on stdout. Everything else goes to stderr (go-clikit convention), so a script can read stdout also during a live tree.
  • A strict command line. repoctl uses cobratree.Strict. An unknown flag, a bad value, the wrong number of arguments and a selector without nodes are usage errors (exit 2). repoctl does nothing before it rejects a usage error.
  • The exit status is a contract. A script branches on it (exit codes).
  • Only a human changes shared state (safety rules).
  • Deterministic by default. A build uses the commits in repoctl.lock. A node builds only when its commit is not in latest (build.html#plan).
  • Every change of the build state is a commit. repoctl rebuild makes an empty commit. repoctl never pushes a git commit; the Next: line gives the push command.
  • Calm output. Exceptions first, a count for each fold, colour only for a state that needs action (terminal.html#calm).
  • Same conventions as sind. --progress, --progress-log, -v as a count, mcp start, exit 130 for an interrupt and the doctor marks ✓ ! ✗.

Selectors

A selector names nodes. A node is one package built for one target, written PKG@TARGET (model.html#nodes). build, plan, graph, list, show, logs and repo diff take node selectors. checkout, pin, rebuild and upstream act on packages and take only the package part; slurm@el9 there is a usage error. repoctl help selectors prints the rules and examples of this section.

(* EBNF, ISO 14977 *)
selectors       = [ selector , { separator , selector } ] ;
separator       = "," | white-space ;           (* several args are a union too *)
selector        = [ "!" ] , ( node-selector | target-selector | here ) ;
node-selector   = pkg-pattern , [ "@" , target-pattern ] ;
target-selector = "@" , target-pattern ;
here            = "." ;                         (* the package of the current directory *)
pkg-pattern     = glob ;                        (* matched against packages[].id *)
target-pattern  = glob ;                        (* matched against targets[].id *)
glob            = gchar , { gchar } ;
gchar           = letter | digit | "-" | "_" | "+" | "." | "*" | "?" | class ;
class           = "[" , [ "!" | "^" ] , cchar , { cchar } , "]" ;
cchar           = letter | digit | "-" | "_" | "+" | "." ;
(* "*" and "?" never match "@". A glob uses the Go path.Match rules. *)

Evaluation

  1. Start with all nodes of the set. packages[].targets limits them, so rocm-smi has no el10 node. A retired target has no nodes.
  2. Remove the nodes of the targets that --target does not name.
  3. Without a positive selector, select all remaining nodes. Else select the union of the positive selectors.
  4. Remove the nodes of each ! selector. The order of the selectors has no effect.
  5. Each positive selector must select at least one node, else exit 2. The error gives the cause: unknown package (with "did you mean"), unknown target, not built for this target, or removed by --target.
  6. . is the package whose worktree holds the current directory. Outside a worktree, it is a usage error.

Quote globs and !. Else the shell expands pmix*, and bash reads ! as history.

Dependency expansion

For build, plan and graph, the selected nodes are the roots. A dependency is always a node of the same target. A needed dependency builds first, or comes from latest or a staging (build.html#deps). The plan action of a node comes from its own commit, not from its dependencies (build.html#actions).

  • A change in ucx never selects slurm. The soname check and closure.broken say when a rebuild is necessary; then a human runs repoctl rebuild.
  • --with-deps adds the transitive dependencies, --rdeps the transitive dependents. In build, they matter only with --force.
  • Nodes that are not selected and not needed get the action skip. The JSON result always has them.
  • A run of a subset is partial. Publish takes the plan, not one run (publish.html#takes).

Exit codes

repoctl attaches a code with cobratree.Coded where it knows the cause. main reads it with cobratree.Status; a usage error gives 2, every other error 1. The constants are in internal/cli/exit.go.

A failed command has the problem code in errors[].code and the exit code in errors[].exitCode. contract.html#problems gives each problem code with its exit code and hint; each command block names its problem codes.

0ExitOKSuccess. Warnings do not change the exit status.
1ExitFailedThe command ran and failed: git or a tool failed, a file or a REPOCTL_* value is invalid, or repoctl found no set.

6ExitNeedsConfirmationA human must confirm, and the confirmation is missing or wrong: no terminal, a wrong answer, no typed key id, or a UI confirmation that does not match (confirmation).

8ExitDoctorWarningOnly with doctor --strict: a check gave a warning, none failed.
9ExitHostNotReadyA required host check failed, in doctor or in the preflight of build, publish, check or mock. A UI or MCP server that runs an older binary than the one on disk also gives 9.

130ExitInterruptedSIGINT, SIGTERM or repoctl cancel. repoctl stopped its children and kept the staging (build.html#cancel).

Restore, resign, prune, sign retire, sign remove, sign deployed and sign removed also use exit 12, and build stops with 12 for a retired set. A first publish stops with 12 when repo.url already serves a repo (publish.served-exists) or the served tree names another set (set.renamed).

The remote set branch can stop a publish with 13 (sign.trust-behind). It counts only when its tip has another repoctl.yaml or keys/ than the set commit of the publish. Exit 13 also comes from an advisory gate that cannot read a repo.

Exceptions: mock shell exits with the status of the shell or of its command. ui and mcp start exit 0 on SIGINT or SIGTERM, because a signal is the normal way to stop a server.

Create the worktrees packages/PKG, or move them to the lock commits. repoctl fetches a missing commit from defaults.git.remote. An external package gets its worktree from a bare clone in ~/.local/share/repoctl/git/ (lifecycle.html#clones). repoctl adds each worktree path to .git/info/exclude.

Each worktree is attached to its local branch: the branch BRANCH of the package entry, with the upstream origin/BRANCH. It is in the repository of the worktree: the set repository or the bare clone. A commit in packages/PKG goes to the local branch, and git -C packages/PKG push origin BRANCH pushes it.

  • checkout moves a local branch only forward. It never moves a branch back, and it never discards a commit or a change.
  • A worktree with uncommitted changes stays as it is: dirty, warning worktree.dirty, hint: commit, then repoctl pin PKG.
  • A worktree that the human moved to another branch or to a detached HEAD stays as it is. Its lock state comes from its HEAD. git -C packages/PKG switch BRANCH attaches it again.
  • For a commit on a detached HEAD, each hint gives git -C packages/PKG push origin HEAD:BRANCH.
  • A kept worktree is a warning, not an error. It gives exit 0 on every surface: CLI, web UI and MCP.
  • With more than one package, checkout continues after a package that fails. Each failed package gets a row with its problem code, and checkout exits 1. The other worktrees stay.

Rules for shared state

Rule

A shared-state command has a dry run, a summary, a typed confirmation, the set lock, a journal and no MCP tool.

  1. Dry run. --dry-run shows the summary and runs the checks; it signs, writes and pushes nothing. repo prune and repo gc do a dry run by default and act only with --apply.
  2. Summary first. The summary goes to stdout before the question (publish.html#summary).
  3. Typed confirmation. The human types the set name (slurm-26.05), not y. For a trust change, the human first types each added key id (signing.html#trust-block). sign deployed and sign removed ask for the key id.
  4. Default answer no. Another text, an empty line or EOF is no: exit 6.
  5. No terminal, exit 6. A terminal means that stdin and stderr are terminals. The question goes to stderr; the answer comes from stdin.
  6. --yes skips the question on a terminal. Without a terminal, it needs REPOCTL_ALLOW_UNATTENDED_PUBLISH=1. It never accepts an advisory (exit 12) and never confirms a trust change (exit 6, sign.trust-change).
  7. REPOCTL_ALLOW_UNATTENDED_PUBLISH=1 allows publish, repo push, repo restore, repo prune and repo resign without a human. It never allows repo gc, sign deployed, sign removed, a trust change or --accept-advisory. repoctl reads it only from the process environment, never from a config file. ui and mcp start remove it from the environment of each child. The journal and the snapshot annotations record unattended: true.
  8. Set lock and journal for the whole run (contract.html#journal).
  9. No MCP tool. The command is in notExposed, in the deny list of the skills and in the guard hook (agents.html#deny). MCP never signs.
  10. humanAction. A skill that reaches such a step stops and gives the human the command (agents.html#human-action). The values are publish, repo-push, restore, prune, gc, resign, sign-deployed, sign-removed, trust-change and accept-advisory.
  11. The UI has the same steps: the summary, the typed key ids of a trust change and the typed set name (ui-publish.html#confirm). It never passes --yes to a child; it gives the child a UI confirmation.

UI confirmation

A child of the web UI has no terminal, and repoctl ui removes REPOCTL_ALLOW_UNATTENDED_PUBLISH from its environment. Thus --yes cannot work for it. In its place, the server gives the child a UI confirmation: the values that the human typed in the dialog, for one command.

  1. Content. One JSON object. It holds the command (publish or sign deployed), the typed set name and the accepted advisory ids. It also holds the typed key ids: each added key of a trust change, or the key of sign deployed. For publish, it holds the plan digest of the review.
  2. One use. The server writes the object into a pipe. The child gets the read end as file descriptor 3 and the hidden flag --confirm-fd 3. The child reads the object once and closes the pipe. The object never goes on the command line, into the environment or into a file. The help and the completion do not show the flag.
  3. Origin. The child accepts --confirm-fd only when its parent process is the server that ui.json names (ui.html#sets). Else it stops with publish.needs-confirmation (exit 6).
  4. Match. The child compares the object with its command line: the set name with the set, and the advisory ids with the --accept-advisory flags. The key ids must equal the added keys of the trust block, or the ID of sign deployed. A difference stops it with publish.needs-confirmation (exit 6).
  5. Plan digest under the set lock. publish takes the set lock, runs step check and makes the plan digest again. When it differs from the plan digest of the object, publish stops before the first signature with publish.plan-changed (exit 6). The human must review the publish again.
  6. Record. The journal and the snapshot annotations record origin ui and unattended: false.

Plan digest

The plan digest is the sha256 of the publish summary as canonical JSON. It covers the base digest and the NVRs to sign of each target and the signer fingerprint. It also covers the added and removed keys of the trust block and the accepted advisory ids.

Thus another latest, other staged nodes, another sign.key or another key file give another plan digest. publish --dry-run --json gives the plan digest in Run.planDigest. The review page shows the summary of that dry run, and the confirm dialog sends the plan digest back (ui-publish.html#confirm).

Error message style guide

Form

repoctl: ✗ build: failed in 41m07s: 6 ok, 1 failed, 1 blocked, 13 current    (summary line, if a display ran)
repoctl: error: OBJECT: WHAT HAPPENED
hint: WHAT TO DO. run: CMD                                                     (0 to 3 lines)
  • The error line starts with repoctl: error: . It names the exact object (node, run, file, flag), then the cause. It has no full stop at the end.
  • Each hint is one instruction in the imperative, about a finding in this output. The command to copy comes last, after run: . A hint never says "maybe" or "try". Static help goes to repoctl help TOPIC.
  • Use the words of the model: slurm@el10, not "the slurm build for EL10".
  • Name the source of a bad value: the flag, the variable (REPOCTL_JOBS="four") or the file and key (repoctl.yaml: packages[3].targets).
  • For a bad flag value, use the go-clikit form: invalid --progress value "fancy": want auto, tree, counter, plain or none.
  • Quote at most one line of another program, escaped. Point to the log for the rest.
  • Do not write "please", "sorry", "successfully", "simply" or "just", and no exclamation marks. Show a Go stack trace only with -vvv.
  • With --json, the same text is in errors[].message and errors[].hint, with a stable errors[].code (contract.html#problems).
  • A failed command ends with hints, the normal path with Next: (hint and Next lines).
