CLI reference

This chapter specifies the repoctl command line. It gives the command tree, the global flags, the selectors, the output rules, the exit codes and one block for each command. It also gives the shared-state safety rules, the help topics, shell completion, the migration from the bash scripts and the error message style.

  • The CLI, the web UI and the MCP server use one core. The words, the selectors and the exit codes of this chapter apply to all three.
  • 47 command blocks in eight groups. Each command has one safety class: read, staging, local write or shared state.
  • Results go to stdout. Progress, notes, warnings, hints and errors go to stderr.
  • Human output shows the exceptions and a totals line. -v shows all rows. Scripts use --json.
  • The exit codes 0 to 13 and 130 are a contract. repoctl can add a code, but it never renumbers a code.
  • A shared-state command has a dry run, a summary, a typed confirmation, the set lock, a journal and no MCP tool.
  • A failed command ends with one error line and 0 to 3 hints. The normal path ends with one Next: line.

Principles

  • Same words everywhere. A command name, a flag, a column header and a JSON field use the same word of the model (model.html#glossary).
  • Results on stdout. Everything else goes to stderr (go-clikit convention). A script can read stdout of every command, also while a live tree is on the terminal.
  • A strict command line. repoctl uses cobratree.Strict. An unknown flag, a bad value, the wrong number of arguments and a selector that selects no node are usage errors (exit 2). repoctl does nothing before it rejects a usage error.
  • The exit status is a contract. A script branches on it (exit codes).
  • Only a human changes shared state. A shared-state command shows a summary and asks for the set name. The MCP server has no tool for it (safety rules).
  • Deterministic by default. A build uses the commits in repoctl.lock. A node builds only when its commit is not in latest (build.html#plan).
  • Every change of the build state is a commit. repoctl rebuild makes an empty commit. repoctl never pushes a git commit; the Next: line gives the push command.
  • Calm output. Exceptions first, a count for each fold, colour only for a state that needs action (terminal.html#calm).
  • Same conventions as sind. --progress, --progress-log, -v as a count, mcp start, exit 130 for an interrupt and the doctor marks ✓ ! ✗.

Selectors

A selector names nodes. A node is one package built for one target, written DIR@TARGET (model.html#nodes). build, plan, graph, list, show, logs and repo diff take node selectors. checkout, pin, rebuild and upstream act on packages and take only the package part; slurm@el9 there is a usage error.

(* EBNF, ISO 14977 *)
selectors       = [ selector , { separator , selector } ] ;
separator       = "," | white-space ;           (* several args are a union too *)
selector        = [ "!" ] , ( node-selector | target-selector | here ) ;
node-selector   = pkg-pattern , [ "@" , target-pattern ] ;
target-selector = "@" , target-pattern ;
here            = "." ;                         (* the package of the current directory *)
pkg-pattern     = glob ;                        (* matched against packages[].dir *)
target-pattern  = glob ;                        (* matched against targets[].id *)
glob            = gchar , { gchar } ;
gchar           = letter | digit | "-" | "_" | "+" | "." | "*" | "?" | class ;
class           = "[" , [ "!" | "^" ] , cchar , { cchar } , "]" ;
cchar           = letter | digit | "-" | "_" | "+" | "." ;
(* "*" and "?" never match "@". A glob uses the Go path.Match rules. *)

Evaluation

  1. Start with all nodes of the set. packages[].targets limits them, so rocm-smi has no el10 node. A retired target has no nodes.
  2. Remove the nodes of the targets that --target does not name.
  3. Without a positive selector, select all remaining nodes. Else select the union of the positive selectors.
  4. Remove the nodes of each ! selector. The order of the selectors has no effect.
  5. Each positive selector must select at least one node, else exit 2. The error gives the cause: unknown package (with "did you mean"), unknown target, not built for this target, or removed by --target.
  6. . is the package whose worktree holds the current directory. Outside a worktree, it is a usage error.

Quote globs and !. Else the shell expands pmix*, and bash reads ! as history.

Dependency expansion

For build, plan and graph, the selected nodes are the roots. A dependency is always a node of the same target. The plan action of a node comes from its own commit, not from its dependencies (build.html#actions).

  • Needed dependencies. A node that builds needs the RPMs of its dependencies. A dependency with the action build builds first in the same run. A current dependency comes from the local copy of latest, a staged one from the staged view of the plan (build.html#staging).
  • No rebuild of dependents. A change in ucx never selects slurm. The soname check and closure.broken say when a rebuild is necessary; then a human runs repoctl rebuild.
  • --with-deps adds the transitive dependencies to the selection, --rdeps the transitive dependents. In build, they matter only with --force.
  • Nodes that are not selected and not needed get the action skip. The JSON result always has them.

Output rules

Streams

  • stdout holds the result only: a table, a key-value block or one JSON document.
  • stderr holds, in order: progress, note: and warning: lines, log lines, the summary line, the error line, 0 to 3 hint: lines and Next:. A confirmation question also goes to stderr.
  • Progress never changes stdout. A command that ends in less than one second draws no progress and no summary line.
  • repoctl never writes a token or a passphrase into a log, a journal or a result.

terminal.html#streams shows the streams. The words for node states are in build.html#states.

Human output

  • Exceptions plus a totals line. A result table shows the rows that differ from the normal state (in-sync, in-tree, ok, current, same, up-to-date). The normal rows fold into one totals line with a count for each state. Example: 11 packages: 9 in-sync, 1 ahead, 1 in tree (-v shows all). The count stays, so "all fine" and "nothing checked" do not look the same.
  • -v shows all rows. Scripts do not parse the text. They use --json, which always has all rows.
  • A column with the same value on every row moves into the header line. A list where all items pass folds to one line.
  • A pure list (list, repo ls, runs, sign ls, repo snapshots) shows all rows, because it has no normal state to fold.

JSON output

With --json, a command writes exactly one JSON document to stdout: the envelope with apiVersion, kind, metadata, items, warnings and errors (contract.html#envelope). Each command block names its kind (contract.html#kinds). A failed command also writes an envelope. items holds the partial result. errors holds each problem with its code, hint and exit code, and humanAction where a human must act.

A usage error writes no envelope. --json does not change the progress; in CI, use --progress plain or none.

Colour and layout

Colour shows only on a terminal, and never with NO_COLOR, --no-color or TERM=dumb. Tables have no colour: a table shows a state with a word or a mark. Without a UTF-8 locale, repoctl writes the ASCII marks, for example # build, o queued and / blocked. All lines fit in 120 columns. terminal.html#marks gives the marks and colours; terminal.html#layout gives the layout of ids, digests and durations.

Hint and Next lines

  • hint: WHAT TO DO. run: CMD tells what to do about a finding in this output: an error or a warning. A failed command ends with 0 to 3 hints and has no Next: line.
  • Next: CMD gives the one next step of the normal path. status computes it from the state and writes it as its last line. pin, rebuild, a successful build and publish write it at the end. init, migrate, sign add, sign deployed and a prune dry run also end with it.
  • When the step needs more than one command, the commands follow on indented lines. init and migrate write a numbered list.
  • With --json, the field next holds the step as NextStep objects: in the item of Status, Run and SignerList, and in metadata.next of Lock and File (contract.html#kinds).

Commands

Each block gives the synopsis, what the command does and the flags that need an explanation. Four facts follow: the set lock (build.html#lock), the files that the command writes, the kind of the --json result and the exit codes. Paths use the XDG defaults (config.html#xdg). The examples use the story: set slurm-26.05 on hpc-a1, run r-20261102-1750-a3f and publish p-20261103-1412-5e1.

Workspace commands

repoctl init local write

repoctl init [--name NAME] [--repo NAME] [--add-target ID=MOCKCFG]... [--force]
repoctl init --from SET --name NAME [--force]

Write a starter repoctl.yaml and an empty repoctl.lock in the start directory (config.html#set-config). init creates no branch and no worktree. Without --from, the default target is el9=rocky+epel-9-x86_64, and --repo defaults to the first part of the set name.

With --from SET, init forks a set directory or a builder branch. It replaces the old set name in each branch name and keeps the other keys. init lists a branch without the old set name as "shared branch". It keeps the active keys and drops the retiring and removed keys. It writes an empty repoctl.lock and does not copy .repoctl/advisories.yaml or keys/deployed.yaml; in a fork, it deletes them (lifecycle.html#init-from).

init ends with a Next: list. With --from, it is repoctl help new-set from step 3. Without --from, it is the steps of repoctl help packages for the first package (lifecycle.html#help).

repoctl checkout local write

Create the worktrees packages/DIR, or move them to the lock commits. repoctl fetches a missing commit from defaults.git.remote. An external package gets its worktree from a bare clone in ~/.local/share/repoctl/git/ (lifecycle.html#clones). repoctl adds each worktree path to .git/info/exclude.

Each worktree is attached to its local branch: the branch BRANCH of the package entry, in the repository of the worktree (the set repository or the bare clone), with the upstream origin/BRANCH. A commit in packages/DIR goes to the local branch. git -C packages/DIR push origin BRANCH pushes it. checkout compares the local branch with the lock commit:

  • A worktree with uncommitted changes stays as it is: dirty, warning worktree.dirty, hint: commit, then repoctl pin DIR.

  • A kept worktree is a warning, not an error. It gives exit 0 on every surface: CLI, web UI and MCP.
  • --force resets the local branch to the lock commit and discards the changes. Commits that only this branch holds are lost.

The repository commands take the global --target; the default is all targets. The publish runs (publish, repo push, repo restore, repo prune --apply, repo gc --apply, repo resign) follow the shared-state safety rules.

Upgrade repoctl

The text of repoctl help upgrade gives the steps on one admin host. A run that is active during the upgrade ends with the old binary. A UI or MCP server that runs during the upgrade starts no new child (host.stale-server).

UPGRADE

Upgrade repoctl on an admin host:
  1. Read the release notes. They name new keys and fields, a new
     apiVersion and a new minRepoctl.
  2. repoctl runs --state running    in each set: wait until no run is active
  3. repoctl ui --stop               stop the web UI server
  4. sudo dnf upgrade repoctl repoctl-release
  5. repoctl skills install          also --project in each set that has them
  6. repoctl check --install-timer   in each set with a timer: it rewrites
                                     the units when they changed
  7. Restart each agent session that runs "repoctl mcp start".
  8. repoctl doctor                  host.stale-server, skills.version-mismatch
                                     and check.timer-unit must pass
Upgrade the mirror job on the HTTP server: sudo dnf upgrade
repoctl-mirror. The timer runs the new job at its next start.
Two admins can work with two releases for a short time. An older
binary reads newer files, but it never rewrites a file with a field
that it does not know (contract.newer-file, exit 1).

  - raise minRepoctl in repoctl.yaml if the release notes ask for it;
  - for a new apiVersion, upgrade the HTTP server first, then run

Rules for shared state

Rule

A shared-state command has a dry run, a summary, a typed confirmation, the set lock, a journal and no MCP tool.

  1. Dry run. --dry-run shows the summary and runs the checks; it signs, writes and pushes nothing. For repo prune and repo gc, the dry run is the default, and --apply acts.
  2. Summary first. The summary goes to stdout before the question (publish.html#summary).
  3. Typed confirmation. The human types the set name (slurm-26.05), not y. For a trust change, the human first types each added key id, then the set name (signing.html#trust-block). sign deployed and sign removed ask for the key id.
  4. Default answer no. Another text, an empty line or EOF is no, and the command stops with exit 6.
  5. No terminal, exit 6. A terminal means that stdin and stderr are terminals. The question goes to stderr; the answer comes from stdin.
  6. --yes skips the question on a terminal. Without a terminal, it works only with REPOCTL_ALLOW_UNATTENDED_PUBLISH=1. --yes never accepts an advisory (a blocking advisory gives exit 12) and never confirms a trust change (exit 6, sign.trust-change).
  7. REPOCTL_ALLOW_UNATTENDED_PUBLISH=1 allows publish, repo push, repo restore, repo prune and repo resign without a human. It never allows repo gc, sign deployed, sign removed, a trust change or an advisory acceptance (--accept-advisory). repoctl reads it only from the process environment, never from a config file. ui and mcp start remove it from the environment of each child. The journal and the snapshot annotations record unattended: true.
  8. Set lock and journal. The command holds the set lock for its whole run and writes a journal (contract.html#journal).
  9. No MCP tool. The command is in notExposed, in the deny list of the skills and in the guard hook (agents.html#deny). MCP never signs.
  10. humanAction. A skill that reaches such a step stops and gives the human the command (agents.html#human-action). The values are publish, repo-push, restore, prune, gc, resign, sign-deployed, sign-removed, trust-change and accept-advisory.
  11. The UI has the same two steps, the summary and the typed set name (ui-publish.html#confirm). It never passes --yes to a child without that confirmation.

Error message style guide

Form

repoctl: ✗ build: failed in 41m07s: 6 ok, 1 failed, 1 blocked, 13 current    (summary line, if a display ran)
repoctl: error: OBJECT: WHAT HAPPENED
hint: WHAT TO DO. run: CMD                                                     (0 to 3 lines)
  • The error line starts with repoctl: error: . It names the exact object (node, run, file, flag), then the cause. It has no full stop at the end.
  • Each hint is one instruction in the imperative, about a finding in this output. The command to copy comes last, after run: . A hint never says "maybe" or "try". Static help goes to repoctl help TOPIC.
  • Use the words of the model: slurm@el10, not "the slurm build for EL10".
  • Name the source of a bad value: the flag, the variable (REPOCTL_JOBS="four") or the file and key (repoctl.yaml: packages[3].targets).
  • For a bad flag value, use the go-clikit form: invalid --progress value "fancy": want auto, tree, counter, plain or none.
  • Quote at most one line of another program, escaped. Point to the log for the rest.
  • Do not write "please", "sorry", "successfully", "simply" or "just", and no exclamation marks. Show a Go stack trace only with -vvv.
  • With --json, the same text is in errors[].message and errors[].hint, with a stable errors[].code (contract.html#problems).
  • A failed command ends with hints, the normal path with Next: (hint and Next lines).

Examples

The failed build (exit 3) is in the build block; the refused publish (exit 12) is in the publish block.

The lock is dirty (exit 5), at 17:45 before the pin:

$ repoctl build
repoctl: error: ucx: worktree 4b1e9c2 is ahead of repoctl.lock (907c60d)
hint: record the new commit. run: repoctl pin ucx
hint: to try it without a pin (not publishable). run: repoctl build --from worktree

Publish without a human (exit 6):

$ repoctl publish --target el9 --yes < /dev/null
repoctl: error: publish: stdin is not a terminal, and REPOCTL_ALLOW_UNATTENDED_PUBLISH is not set
hint: run the command in a terminal and type the set name when asked
hint: for a dedicated publish job only, set REPOCTL_ALLOW_UNATTENDED_PUBLISH=1 in its environment

A wrong set name (exit 6):

Type the set name to sign 38 RPMs and publish el9 of slurm-26.05: slurm
repoctl: error: publish: "slurm" is not the set name; nothing is signed or pushed
hint: run the command again and type: slurm-26.05

The set is busy (exit 7), during the story run:

$ repoctl build slurm
repoctl: error: set slurm-26.05 is busy: repoctl build holds the set lock (run r-20261102-1750-a3f, pid 48213 on hpc-a1)
hint: watch that run. run: repoctl runs latest --follow
hint: wait for it. run: repoctl build slurm --lock-wait 2h

A selector that selects no node (exit 2):

$ repoctl build rocm-smi@el10
repoctl: error: selector "rocm-smi@el10" selects no node: rocm-smi is not built for el10 (targets: [el9])
hint: build it on its own target. run: repoctl build rocm-smi@el9

latest moved (exit 13): A. Admin on hpc-a2 after the publish of 14:12, before a pull:

$ repoctl plan --target el9
repoctl: error: el9: latest is p-20261103-1412-5e1 (d.klein@hpc-a1), the local copy has p-20260912-1403-c21
hint: update the local copy. run: repoctl repo pull
