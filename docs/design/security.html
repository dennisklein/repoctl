Security model

This chapter specifies the security model of repoctl. It names the assets, the actors and the trust boundaries. It gives the rules that protect the set inputs, the GitHub branches and the agent sessions. It ends with the threats, the public fields and the residual risks. The chapter on signing gives the key rules (Signing and trust).

  • The clients trust only OpenPGP signatures. GHCR, the HTTP server and the network hold signed files, but they are not trusted.
  • The builder branch is the root of trust. It holds sign.keys, the public keys and the deployment records.
  • The admin host is the builder. One human builds, signs and publishes there, with a personal key on a YubiKey.

Assets

An asset is a thing that an attacker wants to read, change or use. The table gives each asset, where it is, what an attacker gets from it and the guard of the design.

#AssetWhereWhat an attacker getsGuard
A1Signing keysThe private key of each admin, on a YubiKey or in a gpg keyring of the admin host.A signature that all clients trust.The card does not give out the key. PIN and touch. Gate 1 (signing.html#gates). Offboarding (signing.html#offboarding).
A2Trust recordssign.keys in repoctl.yaml, keys/ID.asc and keys/deployed.yaml on builder/<set>.A new trusted key, or a key that signs before the clients have it.The trust block, gate 2 and the mirror job (signing.html#trust-block).
A3Set inputsrepoctl.yaml, repoctl.lock, the macros files, the in-tree packages and keys/ on builder/<set>.A change of what the next publish builds, for example a pin to a bad package commit.The publish summary (publish.html#summary).
A4Package sourcesThe package branches and the source archives of upstream.Bad code in a build.The lock pins each package commit. A human reviews each version bump. The provenance records the digest of each source and buildroot RPM (supply-chain.html#provenance).
A5SnapshotsGHCR: the snapshot artifacts and the tag latest.A change of what the mirror job pulls.Each RPM and each repomd.xml.asc is signed. The mirror job verifies them (publish.html#mirror).
A6Served treeThe HTTP server.A change of what the clients download.dnf checks repomd.xml.asc and rpm checks each RPM (signing.html#chain).
A7Client keyringsThe rpmdb keys and the dnf repository keyring of each client.Trust for any key.Only the release package and config management write them.
A8CredentialsThe GHCR token of each admin in the container credential store. The GitHub login with push access to the set repository.A push of snapshots and tags, a delete of snapshots, a push of commits.Team membership and package access (publish.html#registry). A9The toolrepoctl and its skills on branch main, the release RPMs of repoctl and the mirror job script contrib/mirror/.Code that runs on each admin host and on the HTTP server.The records of the tool (supply-chain.html#tool).

Actors

An actor is a human or a process that can change an asset. The table gives what each actor has and what it can do in the design.

ActorHasCan
AdminAn active and deployed key, push access to the set repository, a GHCR token.Build, sign and publish. Change the trust records.
New adminAn active key without a deployment record.Build into staging. A publish stops at gate 2 (signing.html#onboarding).
LeaverA retiring or removed key. Push access and a token until the offboarding ends.Gate 1 refuses the key. The access ends with step 6 of the offboarding (signing.html#offboarding).
Agent in a terminalThe permissions of the human, limited by the tool list of the skill (agents.html#tool-lists).Read, build into staging, edit and commit in a package worktree. It never pushes, publishes or signs.
UI agentThe read-only MCP server (agents.html#ui-agent).Read.
Organization ownerOwner rights in the GitHub organization.Set the rulesets, the package visibility and the team members.
Config managementRoot on the clients and on the HTTP server.Install the release package. Remove a key from the clients.
Mirror jobA system user on the HTTP server and an anonymous pull token.Serve a tree that its key file verifies, and no other tree.
Clientdnf and rpm with the keys of the release package.Install a package that verifies.
Outside attackerAnonymous read access to GHCR and to a public set repository. Possibly a stolen token or a stolen login.Read the public data. With a stolen token: push to GHCR. With a stolen login: push to GitHub.

Trust boundaries

A trust boundary is a line where data goes from one zone to another zone with a different trust. Each crossing has a check. The diagram shows the zones, and the table gives the check of each crossing.

#CrossingCheck at the crossing
B1Admin host and GitHub: set commits and package commits, push and fetch.Publish checks that the set inputs are committed and pushed (publish.html#checks). The lock pins each package commit.
B2Upstream to the admin host: source archives and buildroot RPMs.mock checks the signatures of the Rocky and EPEL RPMs. The provenance records each digest. A human reviews each version bump.
B3Admin host to GHCR: the push of a snapshot and the tag.The GHCR token. GHCR is storage only: nothing in it is trusted without its OpenPGP signature.
B4GHCR to the HTTP server: the pull of the mirror job.The mirror job verifies each repomd.xml.asc and each RPM with the key file that config management installed (publish.html#mirror).
B5HTTP server to the clients: dnf over HTTPS.repo_gpgcheck=1 and gpgcheck=1 with the client keyrings (signing.html#chain).
B6Config management to the clients and the HTTP server: the release package and the key removal.Outside repoctl. A human confirms the result with a deployment record (signing.html#deployment-record).
B7Agent session to the admin host: tool calls.The tool list of the skill, the MCP server without shared-state tools and the deny list (agents.html#deny).
