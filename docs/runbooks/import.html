Import the existing repositories

This runbook converts the published repos of the bash-era scripts into sets that repoctl builds and publishes. The reader is an agent (for example, Claude Code) that works with a human. repoctl has no import command and no UI for this work.

  • One set at a time, one target (el9). Nothing builds.
  • The import keeps the bytes and the signatures of the published RPMs.
  • Each published NVR maps to a commit. The map becomes the adopted entries of the RepoManifest.
  • The human records the deployment of the bash-era key hpc-repo and pushes the first snapshot p-import-YYYYMMDD.
  • The mirror job then serves the same RPM files at the same URL. No client changes.
  • A failed check is a stop. The agent reports it and waits.

Rules for the agent

  • Do the steps in order. Do one set at a time: slurm-26.05, then slurm-25.11, then slurm-25.11-testing.
  • Steps marked human are for the human. Stop, show the exact command and wait. Do not sign, do not push to git, do not push to the registry and do not change the HTTP server.
  • Do not rebuild a package.
  • When a check in this runbook fails, stop. Report the check, the output and the step. Do not find a way around it.
  • Keep a log of each command and its output in $XDG_STATE_HOME/repoctl/import/SET.log.

repo.example.org stands for the HTTP server that serves the bash-era repos. The import keeps the URL, so the clients need no change. Each served directory has three repos (slurm, slurm-source, slurm-debuginfo) and the link slurm-release.rpm. Each repo has packages/, repodata/ with repomd.xml.asc, and RPM-GPG-KEY. The only target is el9 (rocky+epel-9-x86_64).

Check each precondition. When one is not true, stop and tell the human.

  1. The host runs Fedora. repoctl comes from the Fedora repo on GitHub Pages or from a release RPM (where the tool lives). repoctl version supports repo push --from.
  2. These tools are installed: git, rpm, rpmkeys, rpmspec, rpmautospec, createrepo_c, modifyrepo_c, gpgv, jq, rsync, check-jsonschema.
  3. The GitHub organisation and the GHCR namespace of store.oci are final (open question). The clone has all branches: git fetch origin '+refs/heads/*:refs/remotes/origin/*'.
  4. The registry has no snapshot of the set and target: repoctl repo snapshots --target el9 lists nothing. repo push --from works only on an empty package; otherwise it stops with import.not-empty.
  5. The human has a byte copy of each served tree, or gives you a path to one (for example, rsync -a HOST:/srv/packages/slurm-26.05/ DIR/). A copy through HTTP is also correct when the repomd check of Copy item 2 passes.
  6. The human who pushes (Push) holds the secret key of hpc-repo. The repoctl user config on that host selects it: sign.key: hpc-repo.

Convert the builder branch to a set

  1. Make a worktree: git worktree add DIR origin/builder/SET -B builder/SET, for example ~/src/slurm-repo-25.11 for slurm-25.11. Work in DIR.
  2. Run repoctl migrate --dry-run (command block). Read the findings. A difference between the hand order of scripts/build and the graph is not an error. Write it in the report.
  3. Run repoctl migrate. It writes repoctl.yaml, repoctl.lock and rpm/macros.
  4. Compare repoctl.lock with packages.lock: the same dirs, branches and commits. A difference is a stop.
  5. Edit repoctl.yaml (keys):
    • name: SET and repo.name: slurm.
    • One target el9: mock: rocky+epel-9-x86_64, plugins: [rpmautospec], macros: [rpm/macros], path: el9.
    • repo.url: the served URL without the target, for example https://repo.example.org/slurm-26.05.
    • store.oci: ghcr.io/gsi-hpc/slurm-repo.
    • The release package: dir: slurm-release, path: packages/slurm-release, role: release.
    • The bash-era repo key in sign.keys with id hpc-repo and state active. It must be active, because a retiring key makes no new signatures, also not on repomd.xml. It goes to retiring later, after the personal keys are deployed (offboarding and rotation). Compare the fingerprint with gpg --show-keys --with-fingerprint packages/slurm-release/RPM-GPG-KEY-slurm.
    • Keep a shared branch as it is. Example: slurm-25.11 pins pmix_v4 on pmix/slurm-26.05-v4.
  6. Run repoctl status. It must read the set without an error. An unknown key or a bad value is an error.
  7. Check that each pinned commit is on its remote branch: git merge-base --is-ancestor COMMIT origin/BRANCH. Publish refuses a commit that is not on the remote (checks). A commit that is not on the remote is a stop. The human must push it or change the pin.
  8. Run repoctl checkout. Each package is in-sync.
  9. Update CLAUDE.md: replace the script commands with repoctl commands. Point to repoctl help packages and repoctl help new-set (help topics).
  10. Commit. Do not delete the old files yet (Remove). 
    git add repoctl.yaml repoctl.lock rpm/macros CLAUDE.md
git commit -m "feat!: convert SET to a repoctl set" -m "- add repoctl.yaml and repoctl.lock from packages.lock
- add the repo key as hpc-repo (active)
- keep the bash-era scripts until the first repoctl publish"
  11. human Review and push: git push origin builder/SET.

Copy and verify the served tree

  1. Put the copy in a new, empty directory: IMPORT=$XDG_STATE_HOME/repoctl/import/SET/el9. Copy with rsync -a --link-dest or cp -a. Do not write into the copy that the human gave you.
  2. For each of the three repos, compare the copy with the served repo. The two values must be equal. 
    curl -fsS URL/REPO/repodata/repomd.xml | sha256sum
sha256sum $IMPORT/REPO/repodata/repomd.xml
    Then check each file that repomd.xml lists: its checksum must be correct. Then check each RPM that primary.xml lists: it exists and its checksum is correct.
  3. Check the metadata signature of each repo: 
    gpg --dearmor < packages/slurm-release/RPM-GPG-KEY-slurm > $TMP/key.gpg
gpgv --keyring $TMP/key.gpg $IMPORT/REPO/repodata/repomd.xml.asc $IMPORT/REPO/repodata/repomd.xml
  4. Check the signature of each RPM with a separate rpm database. Each line must end with digests signatures OK. An RPM with no signature or with another key is a stop. 
    rpmkeys --dbpath $TMP/rpmdb --import packages/slurm-release/RPM-GPG-KEY-slurm
rpmkeys --dbpath $TMP/rpmdb --checksig $IMPORT/*/packages/*.rpm
  5. Find the files in packages/ that primary.xml does not list. Write them in the report. Do not delete them. They do not go into the snapshot.

Map each published NVR to a commit

rpmautospec gives each commit of a package branch its own release. Thus one commit gives one NVR. This step finds the commit of each published SRPM.

  1. List the SRPMs of slurm-source: rpm -qp --qf '%{NAME} %{VERSION} %{RELEASE}\n'. Group the binary and debuginfo RPMs by their SRPM: rpm -qp --qf '%{SOURCERPM}\n'.
  2. For each dir in repoctl.lock (branch B, pinned commit C), get the source package name at C: rpmspec --load=rpm/macros -q --srpm --qf '%{name}' SPEC.
  3. For each commit K in git rev-list C (newest first), compute the NVR. When the NVR equals a published SRPM, record (SRPM, K). Stop the walk when each published SRPM of the name has a commit. 
    git worktree add --detach $TMP/k K
rpmautospec process-distgit $TMP/k/NAME.spec $TMP/out.spec
rpmspec --load=rpm/macros --define 'dist .el9' -q --srpm --qf '%{nvr}' $TMP/out.spec
git worktree remove $TMP/k
  4. For the in-tree release package (packages/slurm-release), walk the builder branch: git log --format=%H -- packages/slurm-release. Compute the NVR at each commit as in item 3. Its build identity is the last set commit that changed its path (release package).
  5. Check the result for each dir:
    ResultAction
    C gives the newest published NVR of the name.Correct. The node is current after the import.
    C gives an NVR that is not published.Correct. The bash-era scripts did not build C yet. plan builds it after the import. Write it in the report.
    The newest published NVR comes from a commit that is not an ancestor of C.Stop. The lock does not match the repo. Ask the human.
    An older SRPM has no commit.Entry with reason: adopted-unmapped and commit: null.
    Two published SRPMs map to the same commit.Stop. Ask the human.
    A published SRPM name has no dir in repoctl.yaml.Correct. The name is retired (retire). Entry with dir: null and reason: adopted-unmapped.
  6. Write the map as a table in the report: dir, SRPM NVR, commit, reason.

Write the manifest

  1. Write one RepoManifest for the target to $XDG_STATE_HOME/repoctl/import/SET/el9.manifest.json. The manifest is for the binary repo (slurm/). It lists the SRPM and the debuginfo RPMs of each build, so slurm-source and slurm-debuginfo get no manifest (snapshot format). The fields of an adopted entry are in adopted manifest entries. 
    {
  "apiVersion": "repoctl/v1alpha1", "kind": "RepoManifest",
  "set": "slurm-26.05", "target": "el9", "publish": "p-import-20260828",
  "builds": [{
    "dir": "munge", "commit": "3a244fd4728f94342beba4a7634c463370a7b877", "url": null,
    "branch": "munge/slurm-26.05",
    "srpm": "munge-0.5.18-1.el9.src.rpm",
    "rpms": ["munge-0.5.18-1.el9.x86_64.rpm", "munge-libs-0.5.18-1.el9.x86_64.rpm",
             "munge-debuginfo-0.5.18-1.el9.x86_64.rpm", "…"],
    "reason": "adopted",
    "mockConfig": null, "macros": null, "buildroot": null, "buildrootFile": null,
    "provides": ["libmunge.so.2()(64bit)", "…"],
    "requires": ["libcrypto.so.3()(64bit)", "…"],
    "run": null, "built": "2026-06-02T09:41:17Z",
    "publish": "p-import-20260828", "signer": "9F2C0B71E4A6C8D0F1A3B5C7D9E1F3A57C3A19F2"
  }],
  "removed": []
}
  2. provides and requires: the union of rpm -qp --provides and rpm -qp --requires of the binary RPMs of the build. Drop the rpmlib(…) entries.
  3. built: rpm -qp --qf '%{BUILDTIME}' of the SRPM, in UTC.
  4. signer: the full fingerprint of the sign.keys entry whose key ID is in rpm -qp --qf '%{RSAHEADER:pgpsig}'.
  5. removed is empty for an import.
  6. Check the file against the schema: repoctl schema manifest > $TMP/m.schema.json, then check-jsonschema --schemafile $TMP/m.schema.json FILE. A failure is a stop.
  7. Do not change the copy of the served tree. repo push --from adds the manifest and signs repomd.xml (Push).

The example values (dates, file lists) are illustrations. Use the values of Map.

Record the deployed key

human Clients of the bash-era repo exist. Thus gate 2 of publish applies to the import (gates). Gate 2 reads only the committed deployment record. The bash-era slurm-release with the hpc-repo key is on all clients. The target has no snapshot yet, so --path tells repoctl to read the release RPM from the copy. Give the human these commands, with the NVR of the served slurm-release.rpm:

repoctl sign deployed hpc-repo --release slurm-release-26.05-1 \
    --target el9 --path $IMPORT \
    --note "bash-era slurm-release on all clients"
git push origin builder/SET

sign deployed asks for the typed key id, writes keys/deployed.yaml and makes the set commit (command block). For slurm-26.05 the record is:

  - key: hpc-repo
    fingerprint: 9F2C0B71E4A6C8D0F1A3B5C7D9E1F3A57C3A19F2
    release: {el9: slurm-release-26.05-1.el9}
    confirmedBy: d.klein
    at: 2026-08-28T14:52:40Z
    note: "bash-era slurm-release on all clients"

Push the first snapshot

human The holder of the hpc-repo key runs:

repoctl repo push --target el9 --from $IMPORT \
    --manifest $XDG_STATE_HOME/repoctl/import/SET/el9.manifest.json

repoctl verifies every RPM against sign.keys and keeps the RPM signatures. It adds the manifest to slurm/repodata with modifyrepo_c and signs the new repomd.xml with the key of the human (one signature). It runs verify and verify-el. Then it pushes the first snapshot with the publish id p-import-DATE and moves latest to it. It refuses when the registry already has a snapshot for the set and target. The command asks for the typed set name (command block, shared-state rules). For slurm-26.05, the result is p-import-20260828: kind import, 48 RPMs, signer hpc-repo.

Verify the import

  1. Run repoctl repo verify --target el9. Expect exit 0.
  2. Run repoctl plan. Each node that Map marked "current" shows current. Only the nodes that Map marked "not published" show build. Any other build is a stop.
  3. Run repoctl check. Write the advisories in the report. retired.published is expected for retired names. A closure.broken advisory is a fact of the published repo, not an import error. Write it in the report.
  4. Run repoctl status. "served: behind" or "served: unknown" is correct until the switch.
  5. Do not run repoctl build --force on an adopted node. Publish refuses an NVR that is already published with other content (build --force).

Switch the HTTP server to the mirror job

human The mirror job pulls latest from GHCR, verifies it with the client keys and swaps the served tree (mirror job). Before the human switches it on:

  1. Run the mirror job once, with a config line whose served path is a test directory.
  2. Compare the test directory with the served tree. The RPM files must be byte-equal. Only slurm/repodata/ and the new repoctl-snapshot.json differ.
  3. Give the human the result. The human switches the job on for the set.

Clients get the new repomd.xml after metadata_expire (one hour). No package changes on a client.

Report

At the end of each set, give the human one report with:

  • The findings of repoctl migrate.
  • The NVR map, with each adopted-unmapped entry and each "not published" node.
  • The files in packages/ that the repodata does not list.
  • The snapshot reference and digest, for example ghcr.io/gsi-hpc/slurm-repo/slurm-26.05-el9:p-import-20260828.
  • The output of plan and check of Verify.
  • Each stop, with the step and the output.

Remove the bash-era files

Do this step after the first publish of the set with repoctl. For slurm-26.05 this is p-20260902-1010-4a7. Until then, the old scripts are the fallback.

git rm -r packages.lock scripts \
    .claude/skills/package-info .claude/skills/list-package-updates
git commit -m "chore!: remove the bash-era build scripts" -m "- repoctl builds and publishes this set now"
