Lost admin host

Use this runbook when an admin host is lost, stolen or broken. The host can hold commits that are not pushed, a key and a registry token. The registry and git keep the team state: see Core model: records and humans and hosts.

  • Stolen, or an attacker controls it: stop its access first. A key on the host is compromised.
  • Broken: a file key that has no other copy is lost.
  • The commits that are not pushed are lost. Make them again on another host.
  • The runs, the staged nodes and the journals of the host are lost. Nothing depends on them.

Rules

  • A human does each step. An agent can run repoctl status, repoctl doctor, repoctl repo snapshots and git log on another host, and it can show the commands. It does not sign, push or revoke (deny list).
  • When you are not sure if another human has the host, treat it as stolen.
  • When a check fails, stop and tell the team.

Example, a variant of the story: on 2026-11-12, the disk of hpc-a2 breaks. A. Admin has the YubiKey with the key a.admin. The host had a commit of repoctl.lock after repoctl pin ucx that was not pushed.

Trigger

  • The disk or the host of an admin is broken, and the host cannot start.
  • An admin host is lost or stolen.
  • An attacker may control an admin host.
  • A host was installed again without the steps "Retire a host" of help team.

Then do Find the lost commits, Check the publishes and Set up a new host.

Stop the access

  1. Delete the registry token of the host. It is the personal access token with write:packages of the admin (registry access).
  2. Delete the git credentials of the host: its SSH key or its token in the GitHub account of the admin.
  3. When the human leaves the team too, an organization owner removes the human from the GitHub team.

Find the lost commits

A publish needs a pushed set commit and pushed package commits (checks). Thus latest never depends on a lost commit: it is only work to make again.

  1. On another admin host, run git fetch origin and git log origin/set/SET. Ask the human of the lost host which commits were not pushed.
  2. Make each lost commit again, and push it at once:
    Lost commitAction
    repoctl sign addRun repoctl sign add ID --fingerprint FPR again. The public key of a new key was in the gpg keyring of the lost host. When nobody has a copy, make a new key (help key).
    repoctl sign deployedRun it again with the same --release or --keyfile value.
    repoctl.lock after repoctl pinRun repoctl checkout, then repoctl pin PKG, and commit. When the package commit is also lost, make it again first.
    .repoctl/advisories.yaml after a dismissRun repoctl advisories dismiss again.
    A commit of an external package in a bare cloneMake the commit again in the external repository, then pin it.
  3. In the example, A. Admin runs repoctl pin ucx on hpc-a1, commits repoctl.lock and pushes the set commit.

Check the publishes

  1. On another admin host, run repoctl repo snapshots --all. Find each publish of the lost host. The annotations give the user and the host.
  2. A publish that did not reach the registry is lost with the host. Publish it again from another host: run repoctl plan, repoctl build and repoctl publish.
  3. A publish of the lost host after the time of the loss is not known. Stop, and use the runbook Key compromise for its signer.

Set up a new host

  1. Do the steps "Add a second admin host" of help team. Install repoctl and clone the set repository. Then run: 
    repoctl doctor
repoctl checkout
repoctl repo pull
repoctl mock update
repoctl check --install-timer
repoctl status
  2. Set sign.key in the user config, and log in to the registry with a new token.
  3. Run repoctl doctor. Each check passes, or warns only for a step of this runbook that is still open.

The check timers of the other admin hosts still run (check timer). Thus the team gets the advisories also before the new host is ready.

Stop conditions

StepStop when
Stop the accessNobody can delete the registry token or the git credentials of the host. Tell an organization owner.
Find item 2A lost commit cannot be made again, for example a commit of an external package that has no copy. Tell the team.
Check item 3A publish of the lost host is not known.

Done when

  • The registry token and the git credentials of the lost host are deleted.
  • Each key of the lost host is revoked, retired or safe on its card.
  • Each lost commit is pushed again. repoctl doctor --only set on the new host shows no git.unpushed.
  • repoctl status on the new host shows local: same for each target.
  • repoctl doctor on the new host shows no check.never and no check.timer-off.
