Registry outage or loss

This runbook is for a registry that does not answer, and for an OCI package or a GitHub organization that is lost. An outage has no break-glass path: the team waits. A lost OCI package gets its last latest back with repoctl repo push --reseed. The rules are in Publish: registry outage and loss.

  • Outage: the mirror job keeps the served tree, and the clients keep working. Publish waits.
  • Loss: re-seed each target from the newest copy of latest. The files and signatures stay as they were, so the clients see no change.
  • The chain before latest is lost. The team agrees to this loss.

Rules

  • A human does each step. An agent can run repoctl status and repoctl repo snapshots, and compare the copies. It does not push (deny list).
  • Do not copy files to the HTTP server by hand. Only the mirror job writes the served tree.
  • When a check in this runbook fails, stop and tell the team.

Trigger

  • Publish, repo pull or status gives registry.unreachable (exit 13), and the journal of the mirror job has pull errors.
  • Publish stops with snapshot.missing (exit 13), or repoctl repo snapshots --target ID lists nothing for a target that was published.
  • The GitHub organization or the OCI package is deleted, or GitHub suspends it.

Outage

  1. Confirm the outage: the GitHub status page shows an incident of GitHub Packages, or repoctl doctor --only registry fails on two hosts.
  2. Tell the team in the team channel. Nobody publishes.
  3. Build and stage the urgent fix with repoctl build. Plan and build use the local copy.
  4. When GHCR answers, run repoctl repo pull, then repoctl publish.

repoctl status shows registry: unknown during the outage. The clients keep the served tree.

Loss of an OCI package or the organization

  1. Confirm the loss: repoctl repo snapshots --target ID lists nothing, and publish stops with snapshot.missing. Tell the team to stop all publishes.
  2. When the namespace is gone, an organization owner makes the organization again, or the team chooses a new namespace. For a new namespace, change store.oci in a set commit, push it, and change the OCI package lines in /etc/repoctl-mirror.conf.
  3. Find the newest copy of latest of each target. Each admin runs jq .publish ~/.local/share/repoctl/SET/repo/TARGET/snapshot.json. On the HTTP server, read repoctl-snapshot.json in the served tree. Take the copy with the newest publish id. The served tree can be behind.
  4. Continue with Re-seed.

Re-seed

  1. On the host with the newest copy, run repoctl repo push --reseed --target ID --dry-run. With a copy of the served tree, add --from DIR. Read the summary: the publish id of the copy, the RPM count and the signers.
  2. Run repoctl repo push --reseed --target ID and type the set name. repoctl verifies the copy, runs verify-el and pushes p-reseed-YYYYMMDD. It signs nothing.
  3. An organization owner sets the new OCI package to public and turns on the inherited access. repoctl doctor --only registry shows registry.public until then.
  4. Do the steps for each other target of the set.
  5. Run repoctl status until it shows served: same. The other admins run repoctl repo pull.

Stop conditions

StepStop when
Loss item 3The copies disagree, and nobody knows which publish was the last latest. Ask each admin for the last publish in the team channel.
Re-seed item 2The re-seed stops with verify.failed or verify.el-failed (exit 10). The copy is not a good tree: use the next newest copy.
Re-seed item 2The re-seed stops with snapshot.exists. Somebody pushed already: run repoctl repo pull and compare.
Re-seed item 5The mirror job does not serve the new latest. Use the runbook Failed mirror job.

Done when

  • repoctl repo snapshots shows a latest for each target.
  • repoctl status shows local: same and served: same on each admin host.
  • repoctl doctor --only registry passes.
  • The next publish passes the freshness check and gate 2.
