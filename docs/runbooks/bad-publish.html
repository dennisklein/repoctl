A bad publish reached the clients

This runbook is for a publish that the mirror job served, and that breaks the clients or must not stay. The normal way back is to fix forward: a new build with a higher release. repoctl repo restore is for a broken repository. The rules are in Publish: restore and fix forward.

  • A bad build: fix forward. Clients update to the fix.
  • A broken repository (bad repodata, a wrong file): restore. latest moves forward to a new snapshot with the older files.
  • dnf does not downgrade. A client that installed the bad NVR keeps it until a newer NVR or config management replaces it.
  • Publish has no rollback flag.

Rules

  • A human publishes and restores. An agent can run repoctl repo diff, repoctl repo verify and the skill triage-build, and it can fix a spec on a package branch. It does not publish (deny list).
  • Do not delete a snapshot with repoctl repo gc to undo a publish.
  • When a check in this runbook fails, stop and tell the team.

The examples use a variant of the story (not the story): the publish p-20261103-1412-5e1 of el9 has ucx-1.22.1-1.el9, and slurm jobs with UCX fail on the clients.

Trigger

  • Clients fail after a dnf upgrade from the repository of the set, and the failure comes from a package of the last publish.
  • dnf makecache fails on all clients of a target, for example with a repodata or signature error.
  • A file in the served tree must not be there, for example an RPM of the wrong target.

Find the bad snapshot

  1. Run repoctl status. Note latest and the served snapshot of each target.
  2. Run repoctl repo snapshots --target el9. Find the last good snapshot, for example p-20260912-1403-c21.
  3. Run repoctl repo diff --from p-20260912-1403-c21 --to p-20261103-1412-5e1 --target el9. It lists the source packages that the bad publish changed.
  4. Run repoctl repo verify --served --el --target el9. Exit 10 means a broken repository.
  5. Decide the path:
    FindingPath
    repo verify passes. One or more builds are bad.Fix forward
    repo verify fails, or a file must leave the repository now.Restore, then fix forward

Fix forward

  1. Fix the package on its branch: revert the bad commit, or fix the spec. Commit and push the package branch. The NVR of the fix must be higher than the bad NVR, because dnf does not downgrade. rpmautospec raises the release for each commit.
  2. Run repoctl pin DIR, commit repoctl.lock and push the set commit.
  3. Run repoctl plan, then repoctl build. Test the staged node.
  4. Run repoctl publish --target el9 and confirm.
  5. When the clients must not wait for the next dnf upgrade, config management updates the package on the clients.

Restore

  1. Run repoctl repo restore p-20260912-1403-c21 --dry-run. Read the summary: it lists each NVR that leaves the repository.
  2. Run repoctl repo restore p-20260912-1403-c21 and type the set name. latest moves to a new snapshot with the files of the older snapshot. The NVRs that leave go into removed[].
  3. Run repoctl status until it shows served: same.
  4. A client that installed a removed NVR keeps it. When it must go, config management runs dnf downgrade NAME on the clients, or the fix forward gives a newer NVR.
  5. Fix forward (above). Publish refuses a build that gives a removed NVR again with other content (nvr.removed). Use repoctl rebuild DIR --reason TEXT for a new release.

Stop conditions

StepStop when
Find item 2No snapshot in the chain is good.
Find item 4The local copy passes, but the served tree fails. The mirror job or the HTTP server is the cause: use the runbook Failed mirror job.
Restore item 2Restore stops with a gate (exit 12) or a verify error (exit 10).
anyThe bad publish holds a secret. Restore takes it out of latest, but older snapshots in the registry still hold it. Tell the team; this runbook does not delete registry history.

Done when

  • latest of each target has the fix, or the restored files and then the fix.
  • repoctl status shows served: same, and repoctl repo verify --served --el exits with 0.
  • The clients that had the bad NVR have the fix or the older NVR.
