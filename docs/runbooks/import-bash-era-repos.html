Runbook: import the bash-era repos into repoctl

Date: 2026-11-03. Status: proposal. The choice of a runbook (no import command) is decided (Q5). Reader: an agent (for example, Claude Code) that works with a person. This runbook converts the three published repos of the bash era into sets that repoctl can build and publish. repoctl has no import command and no UI for this work. The design is in 06 section 8.1 and in 05.

Rules for the agent.

  • Do the steps in order. Do one set at a time. Start with slurm-25.11-testing, then slurm-25.11, then slurm-26.05.
  • Steps marked PERSON are for the person. Stop, show the exact command, and wait. Do not sign, do not push to git, do not push to the registry, and do not change the HTTP server.
  • Do not rebuild a package. The import keeps the bytes and the signatures of the published RPMs.
  • When a check in this runbook fails, stop. Report the check, the output and the step. Do not find a way around it.
  • Keep a log of each command and its output in $XDG_STATE_HOME/repoctl/import/SET.log.

0. Inputs and preconditions

SetBuilder branchServed at (el9)
slurm-25.11-testingbuilder/slurm-25.11-testinghttp://cluster-mirror.hpc.gsi.de/packages/slurm-25.11-testing/el9/
slurm-25.11builder/slurm-25.11http://cluster-mirror.hpc.gsi.de/packages/slurm-25.11/el9/
slurm-26.05builder/slurm-26.05http://cluster-mirror.hpc.gsi.de/packages/slurm-26.05/el9/

Each served directory has three repos (slurm, slurm-source, slurm-debuginfo) and the link slurm-release.rpm. Each repo has packages/, repodata/ with repomd.xml.asc, and RPM-GPG-KEY. The only target is el9 (rocky+epel-9-x86_64).

Check each precondition. When one is not true, stop and tell the person.

  1. The host runs Fedora, and repoctl is installed from the Fedora repo on Pages or from a release RPM (Q16). repoctl version supports repo push --from.
  2. These tools are installed: git, rpm, rpmkeys, rpmspec, rpmautospec, createrepo_c, modifyrepo_c, gpgv, jq, rsync.
  3. The repository is at its final place in GSI-HPC (Q4), and the clone has all branches: git fetch origin '+refs/heads/*:refs/remotes/origin/*'.
  4. The registry has no snapshot of the set and target: repoctl repo snapshots --target el9 lists nothing. repo push --from works only on an empty package (05).
  5. The person has a byte copy of each served tree, or gives you a path to one (for example, rsync -a cluster-mirror:/srv/packages/slurm-26.05/ DIR/). A copy through HTTP is also correct when step 2.2 passes.
  6. The person who runs step 6 holds the secret key of today's repo key (RPM-GPG-KEY-slurm). The repoctl user config on that host selects it as the signing key.

1. Convert the builder branch to a set

  1. Make a worktree: git worktree add ../SET origin/builder/SET -B builder/SET. Work in ../SET.
  2. Run repoctl migrate --dry-run. Read the findings. A difference between the hand order of scripts/build and the graph is not an error. Write it in the report.
  3. Run repoctl migrate. It writes repoctl.yaml, repoctl.lock and rpm/macros.
  4. Check repoctl.lock against packages.lock: the same dirs, branches and commits. A difference is a stop.
  5. Edit repoctl.yaml:
    • name: SET and repo.name: slurm.
    • One target el9, mock: rocky+epel-9-x86_64, plugins: [rpmautospec], macros: [rpm/macros].
    • repo.url: http://cluster-mirror.hpc.gsi.de/packages/SET (05).
    • The store of 05: ghcr.io/gsi-hpc/slurm-repo.
    • The release package: dir: slurm-release, path: packages/slurm-release, role: release.
    • Today's repo key in sign.keys with id hpc-repo and state active (05). It must be active, because a retiring key makes no new signatures, also not on repomd.xml. It goes to retiring later, after the personal keys are deployed (repoctl sign retire hpc-repo, 05). Take the fingerprint from packages/slurm-release/RPM-GPG-KEY-slurm: gpg --show-keys --with-fingerprint.
    • Keep a shared branch as it is. Example: slurm-25.11 pins pmix_v4 on pmix/slurm-26.05-v4.
  6. Run repoctl status. It must read the set without an error. An unknown key or a bad value is an error.
  7. Check each pinned commit is on its remote branch: git merge-base --is-ancestor COMMIT origin/BRANCH. Publish refuses a commit that is not on the remote (Q8). A commit that is not on the remote is a stop. The person must push it or change the pin.
  8. Run repoctl checkout. Each package is in-sync.
  9. Update CLAUDE.md: replace the script commands with repoctl commands. Point to repoctl help packages and repoctl help new-set.
  10. Commit. Do not delete the old files yet (step 10). 
    git add repoctl.yaml repoctl.lock rpm/macros CLAUDE.md
git commit -m "feat!: convert SET to a repoctl set" -m "- add repoctl.yaml and repoctl.lock from packages.lock
- add the repo key as hpc-repo (active)
- keep the bash-era scripts until the first repoctl publish"
  11. PERSON Review and push: git push origin builder/SET.

2. Copy and verify the served tree

  1. Put the copy in a new, empty directory: IMPORT=$XDG_STATE_HOME/repoctl/import/SET/el9. Do not write into the copy that the person gave you. Copy it with rsync -a --link-dest or cp -a.
  2. For each of the three repos, compare the copy with the served repo: 
    curl -fsS URL/REPO/repodata/repomd.xml | sha256sum
sha256sum $IMPORT/REPO/repodata/repomd.xml
    The two values must be equal. Then check each file that repomd.xml lists: its checksum must be correct. Then check each RPM that primary.xml lists: it exists and its checksum is correct.
  3. Check the metadata signature of each repo: 
    gpg --dearmor < packages/slurm-release/RPM-GPG-KEY-slurm > $TMP/key.gpg
gpgv --keyring $TMP/key.gpg $IMPORT/REPO/repodata/repomd.xml.asc $IMPORT/REPO/repodata/repomd.xml
  4. Check the signature of each RPM with a separate rpm database: 
    rpmkeys --dbpath $TMP/rpmdb --import packages/slurm-release/RPM-GPG-KEY-slurm
rpmkeys --dbpath $TMP/rpmdb --checksig $IMPORT/*/packages/*.rpm
    Each line must end with digests signatures OK. An RPM with no signature or with another key is a stop.
  5. Find files in packages/ that primary.xml does not list. Write them in the report. Do not delete them. They do not go into the snapshot.

3. Map each published NVR to a commit

rpmautospec gives each commit of a package branch its own release. Thus, one commit gives one NVR. This step finds the commit for each published SRPM.

  1. List the SRPMs of slurm-source: rpm -qp --qf '%{NAME} %{VERSION} %{RELEASE}\n'. Group the binary and debuginfo RPMs by their SRPM: rpm -qp --qf '%{SOURCERPM}\n'.
  2. For each dir in repoctl.lock, with branch B and pinned commit C:
    1. Get the source package name at C: rpmspec --load=rpm/macros -q --srpm --qf '%{name}' SPEC.
    2. For each commit K in git rev-list C (newest first), compute the NVR: 
      git worktree add --detach $TMP/k K
rpmautospec process-distgit $TMP/k/NAME.spec $TMP/out.spec
rpmspec --load=rpm/macros --define 'dist .el9' -q --srpm --qf '%{nvr}' $TMP/out.spec
git worktree remove $TMP/k
    3. When the NVR equals a published SRPM, record (SRPM, K). Stop the walk when each published SRPM of the name has a commit.
  3. For the in-tree release package (packages/slurm-release), walk the builder branch: git log --format=%H -- packages/slurm-release. Its spec has a fixed release. The identity is the git tree of the path at that commit (04c help keys).
  4. Check the result for each dir:
    ResultAction
    C gives the newest published NVR of the name.Correct. The node is current after the import.
    C gives an NVR that is not published.Correct. The bash era did not build C yet. plan builds it after the import. Write it in the report.
    The newest published NVR comes from a commit that is not an ancestor of C.Stop. The lock does not match the repo. Ask the person.
    An older SRPM has no commit.Entry with reason: adopted-unmapped and commit: null.
    Two published SRPMs map to the same commit.Stop. Ask the person.
    A published SRPM name has no dir in repoctl.yaml.Correct. It is retired (06 section 11.5). Entry with dir: null and reason: adopted-unmapped.
  5. Write the map as a table in the report: dir, SRPM NVR, commit, reason.

4. Write the manifest

  1. Write one RepoManifest for the target to $XDG_STATE_HOME/repoctl/import/SET/el9.manifest.json (03 section 3.2, 06 section 8.1). The manifest is for the binary repo (slurm/). It lists the SRPM and the debuginfo RPMs of each build. slurm-source and slurm-debuginfo get no manifest (05). 
    {
  "apiVersion": "repoctl/v1alpha1", "kind": "RepoManifest",
  "set": "slurm-26.05", "target": "el9", "snapshot": null,
  "builds": [{
    "dir": "ucx", "commit": "907c60d9eb9ff6d099a5edfbfaf82022ba80e662", "url": null,
    "branch": "ucx/slurm-26.05",
    "srpm": "ucx-1.20.0-1.el9.src.rpm",
    "rpms": ["ucx-1.20.0-1.el9.x86_64.rpm", "…"],
    "debuginfo": ["ucx-debuginfo-1.20.0-1.el9.x86_64.rpm", "…"],
    "reason": "adopted",
    "mockConfig": null, "macros": null, "buildroot": null, "buildrootFile": null,
    "provides": ["libucp.so.0()(64bit)", "…"],
    "requires": ["libnuma.so.1()(64bit)", "…"],
    "run": null, "built": "2026-05-28T10:12:44Z",
    "publish": "p-import-20261103", "signer": "…"
  }],
  "removed": []
}
    • provides and requires: the union of rpm -qp --provides and rpm -qp --requires of the binary RPMs of the build. Drop rpmlib(…) entries.
    • built: rpm -qp --qf '%{BUILDTIME}' of the SRPM, in UTC.
    • signer: the key id of rpm -qp --qf '%{RSAHEADER:pgpsig}'.
    • removed is empty for an import (05).
    • The NVRs in this example are not real. Use the values from step 3.
  2. Check the file against the schema: repoctl schema RepoManifest > $TMP/m.schema.json, then validate it with check-jsonschema.
  3. Do not change the copy of the served tree. repo push --from adds the manifest and signs repomd.xml in step 6.

5. PERSON Record the deployed key

Clients exist already. Thus, gate 2 of publish applies to the import (05). Gate 2 reads only the committed deployment record. Today's slurm-release with the hpc-repo key is on all clients. The target has no snapshot yet, so --path tells repoctl to read the release RPM from the copy. Give the person these commands, with the NVR of the served slurm-release.rpm:

repoctl sign deployed hpc-repo --release slurm-release-26.05-1.el9 --path $IMPORT
git add keys/deployed.yaml && git commit -m "chore(keys): record hpc-repo as deployed" && git push

6. PERSON Push the first snapshot

The holder of the hpc-repo key runs:

repoctl repo push --target el9 --from $IMPORT --manifest $XDG_STATE_HOME/repoctl/import/SET/el9.manifest.json

repoctl adds the manifest to slurm/repodata with modifyrepo_c. It signs the new repomd.xml with the key of the person (one signature). The RPM signatures stay. It runs verify and verify-el, then makes the first snapshot with the publish id p-import-DATE and moves latest to it (05). It refuses when the registry already has a snapshot for the set and target.

7. Verify

  1. repoctl repo verify --target el9: exit 0.
  2. repoctl plan: each node that step 3 marked "current" shows current. Only the nodes that step 3 marked "not published" show build. Any other build is a stop.
  3. repoctl check: write the advisories in the report. retired.published is expected for retired names. A closure.broken advisory is a fact of today's repo, not an import error. Write it in the report.
  4. repoctl status: "served: behind" is correct until step 8.
  5. Do not run repoctl build --force on an adopted node. Publish refuses an NVR that is already published with other content.

8. PERSON Switch the HTTP server to the mirror job

The mirror job of 05 pulls latest from GHCR, verifies it and swaps the served tree. Before the person switches it on:

  1. Run the mirror job once into a test directory (05 gives the command).
  2. Compare the test directory with the served tree. The RPM files must be byte-equal. Only slurm/repodata/ may differ.
  3. Give the person the result. The person switches the job on for the set.

Clients get the new repomd.xml after metadata_expire (one hour). No package changes on a client.

9. Report

At the end of each set, give the person one report with:

  • The findings of repoctl migrate.
  • The NVR map of step 3, with each adopted-unmapped entry and each "not published" node.
  • Files in packages/ that the repodata does not list.
  • The snapshot ref and digest of step 6.
  • The output of plan and check of step 7.
  • Each stop, with the step and the output.

10. Remove the bash-era files

Do this step after the first real publish of the set with repoctl. Until then, the old scripts are the fallback.

git rm -r packages.lock scripts .claude/skills/package-info .claude/skills/list-package-updates
git commit -m "chore!: remove the bash-era build scripts" -m "- repoctl builds and publishes this set now"

PERSON Push it.
