Design completeness review

This review examines the design record on branch main at commit f03d25d. It answers three questions. Which areas does no chapter specify? Does the record specify the full lifecycle of each entity? Does it specify each compound workflow from the trigger to the end? Each gap has a proposed fix and the chapter that gets it. This page changes no chapter.

  • The record specifies the normal path well. The create stage is covered for 35 of 48 entities.
  • The weak stages are failure, retire, change and concurrency. Only 7 to 10 of 48 entities have them covered.
  • 14 areas have no chapter. The largest are a security model, incident runbooks and the source inputs of a build.
  • Of 22 compound workflows, three have no design: key compromise, end of life of a set, and testing and production sets.
  • 142 findings: 40 high, 74 medium, 28 low. 31 contradictions between chapters.
  • Eleven work packages close the gaps. Each one must be in the record before a delivery phase starts.

Scope and method

The review reads all pages of the design record: the 17 chapters, the mockup gallery, the contract schemas and examples, and the import runbook. Branch main has no code yet, so the review reads no code.

  1. Read each chapter. List the areas that no chapter specifies (Missing areas).

  2. Put the entities into six groups. For each entity, rate eight lifecycle stages (Entity lifecycles).

  3. List 22 compound workflows. For each workflow, rate nine aspects (Compound workflows).

  4. Record each gap as a finding: the entity and stage, the gap, the sections that were read, a severity and a proposed fix.

  5. Link the findings that describe one gap from two sides. Record each statement that disagrees with another chapter (Contradictions).

  6. Put the fixes into work packages. Map each package to the delivery phase that needs it (Fix plan).
