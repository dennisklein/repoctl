CLI reference

This page lists each command of repoctl with its main flags. repoctl COMMAND --help always shows the full list of flags for your version. The design of each command is in CLI (design).

  • Run repoctl in a set directory, or give it with -C DIR.
  • Add --json to any command for a machine-readable result.
  • A command that changes shared state has --dry-run, a summary and a confirmation.
  • A command that writes the set waits for the set lock only with --lock-wait.

Shared state

Always run --dry-run first for publish, restore, push and resign. For prune and gc, run the command without --apply first.

Files and variables

The set directory holds only committed files and the package worktrees. repoctl keeps all other files in the XDG directories of the user.

WhereWhatSafe to delete?
$XDG_CONFIG_HOME/repoctl/config.yamlThe user config. Edit it by hand.No
$XDG_CACHE_HOME/repoctl/SRPMs, sources, upstream answers, mock files.Yes: repoctl clean --cache
$XDG_DATA_HOME/repoctl/SET/staging/RUN/The RPMs of a run.Use repoctl clean
$XDG_DATA_HOME/repoctl/SET/repo/TARGET/The local copy of latest.Yes: repoctl repo pull

The user config changes only how and where repoctl works, for example jobs, sign.key and ui.listen. It never changes what repoctl builds. The variable REPOCTL_JOBS sets --jobs, REPOCTL_LOCK_WAIT sets --lock-wait, and REPOCTL_SIGN_KEY sets sign.key.

Exit codes

CodeMeaning
0Success. Warnings do not change the status.
1The command ran and failed, or repoctl found no set.
2Usage error: an unknown flag, a bad value, or a selector without nodes.
3A node failed, or a failed node blocks it. Staging and logs stay.
4Nothing to publish, prune, gc or resign.
5A worktree is not in-sync with the lock, or a set input is not committed or not pushed.
6A human must confirm, and the confirmation is missing or wrong.
7Another process holds a lock, and --lock-wait ended.
8Only with doctor --strict: a check gave a warning.
9A required host check failed.
10A signature, a checksum, a record or the repodata is wrong.
11Only with --check: plan, check, upstream or repo diff found something.
12A rule refuses the publish: an NVR rule, an advisory, a signing gate or a retired set.
13The registry or the remote stops the command: latest moved, or a push failed.
130Interrupted by SIGINT, SIGTERM or repoctl cancel.

With --json, a failed command gives the problem code in errors[].code. Use repoctl schema --list for the schemas. The machine contract is in Machine contract.
