Concepts

repoctl has few ideas. Learn them once, and each command has a clear place. This page names them in the order that a change travels.

  • A set is a git directory with repoctl.yaml and repoctl.lock. It builds for one or more targets.
  • A node is one package for one target. A node builds when its commit is not in latest and not in a staging.
  • A build never changes the published repository. Only a human publishes.
  • The snapshot in the registry is the truth. The tag latest points to the newest one.

The journey of a change

Set

A set is one product line, for example slurm-26.05. It lives in a git directory on the branch set/slurm-26.05. The directory holds two committed files and the package worktrees.

PartWhat it is
repoctl.yamlWhat to build: targets, packages, keys, the registry and the public URL.
repoctl.lockThe commit of each package branch that the set uses.
packages/PKGThe git worktree of one package. repoctl checkout makes it.
keys/The public keys that the set trusts.

Generated files do not live in the set directory. They go to the XDG directories of the user. Read repoctl help xdg.

Target

A target is one mock chroot, for example el9 with rocky+epel-9-x86_64. Each target has its own repository, its own snapshots and its own client path. Use --target el9 to limit a command to one target.

Package, node and selector

A package has a spec file and its git history on its own branch, for example ucx/slurm-26.05. A package can also be in the set tree or in an external git repository.

A node is one package built for one target. It is written PKG@TARGET, for example ucx@el9. A selector names nodes. Quote globs and ! in your shell.

You writeYou select
slurmslurm@el9 and slurm@el10
@el10All nodes of el10
'pmix*' '!pmix_v4'All pmix nodes except pmix_v4
.The package of the current directory

Read repoctl help selectors for the full rules.

Lock and pin

The lock makes a build exact. repoctl pin writes the HEAD commit of each worktree into repoctl.lock. A package is in-sync when its worktree is at the lock commit. A package is unpinned when it has no lock line, and orphaned when the lock has a line but repoctl.yaml has no entry. Commit the lock and push it.

Plan and the build state

The published repository is the build state. repoctl builds a node when its commit is not in latest and not in a staging. repoctl plan shows the action of each node and the reason.

ActionMeaning
currentThe commit is in latest. Nothing to do.
stagedBuilt for this lock. Not published yet.
buildNo build of this commit for this target. The reason says why.
skipNot selected, and no selected node needs it.

The reasons of a build are commit-changed, rebuild, new-package, new-target, forced and staging-missing. repoctl does not rebuild dependents by itself. You run repoctl rebuild PKG --reason TEXT when an advisory asks for it.

Run and staging

A run is one execution of build, publish, check or gc. It has an id, for example r-20261102-1750-a3f. A build puts the RPMs of each good node into the staging of its run. Staging is local and unsigned. A node that fails leaves its logs. A node that needs a failed node is blocked.

Publish, snapshot and latest

A publish signs the staged nodes, and pushes a snapshot of each target to the registry. A snapshot is one OCI artifact with all files of the repository. The last step moves the tag latest. Only this step changes what other humans see.

Rule: a human publishes

A command that changes shared state has a dry run, a summary, a confirmation and a journal. In a terminal, you type the set name to confirm. These commands have no MCP tool.

Advisory

An advisory is a check that needs no build. It finds a problem and suggests a fix. Its level is info, warn or required. A required advisory blocks a publish, unless you accept it with --accept-advisory and a reason. You can dismiss info and warn advisories.

Keys and the release package

Each admin signs with a personal key. The set lists the trusted keys, each with a state: active, retiring or removed. The set has a release package, for example slurm-release. It carries the public keys and the .repo file for the clients. repoctl release write writes both files.

The clients get the keys through the release package. After you install it on the clients, record this with repoctl sign deployed. A publish that signs with a key without this record stops with exit 12.
