Operate a set

After the first publish, the work is a loop of small changes. This page gives the steps of the common tasks. Each step names the repository that gets the commit. For a rare task, it points to the help topic or the runbook.

  • Each change ends with repoctl plan. Check the reason before you build.
  • An advisory suggests. You decide. Dismiss a warning only with a written reason.
  • Old versions stay in the repo. Removal is explicit.
  • When a publish goes wrong, stop and open the runbook. Do not improvise.

Bump a package

  1. Run repoctl upstream PKG --releases to see the newer releases.
  2. Run repoctl status. The package must be in-sync. If not, run repoctl checkout PKG.
  3. Edit the spec. Commit in the worktree: git -C packages/PKG commit -am "Bump to X". Repository: the package branch.
  4. Push: git -C packages/PKG push origin BRANCH.
  5. Run repoctl pin PKG. Commit and push repoctl.lock. Repository: the set branch.
  6. Run repoctl plan. Expect the reason commit-changed for PKG.
  7. Run repoctl build. Read the soname result of PKG.
  8. Run repoctl publish, then repoctl status. Expect: served same.

To test a change before you push it, run repoctl build PKG --from worktree. Such a run is not staged.

Add, remove and rename a package

TaskSteps
Add a package in this repositoryAdd id, branch and upstream to repoctl.yaml. Run repoctl checkout --create PKG --from fedora (or --orphan). Write the spec, commit and push the branch. Run repoctl pin PKG. Commit and push repoctl.yaml and repoctl.lock. Plan expects new-package.
Add an external packageCreate the project on the git server first. Then the same steps, with git: {url: …} in the entry.
Build for some targets onlySet targets: [el9] in the entry.
Remove a packageDelete the entry. Run repoctl pin --orphans. Commit and push. Its RPMs stay published. To remove them, run repoctl repo prune --package NAME --all, then again with --apply.
Rename an RPMChange the spec and add Obsoletes. A rename of a package id or a branch does not build.

Read repoctl help packages for the full text. The design is in Sets and packages.

Rebuild with the same version

A library can change its soname. Its dependents then need a rebuild. repoctl never does this by itself.

  1. Run repoctl rebuild PKG… --reason "TEXT". The reason has 8 characters or more. Add --dry-run to see the new NVRs.
  2. Push the package branches. Commit and push repoctl.lock.
  3. Run repoctl plan, repoctl build and repoctl publish.

To rebuild the whole set, run repoctl mock update first, then repoctl rebuild '*' --reason TEXT.

Advisories and upstream

A daily timer runs repoctl check. You can run it by hand too.

$ repoctl check
$ repoctl advisories ls --level required
$ repoctl advisories show ID
$ repoctl advisories dismiss ID --note "known, fixed in the next bump"
$ repoctl upstream --check
  • A required advisory blocks a publish when it concerns a node of that publish.
  • To publish anyway, add --accept-advisory ID --reason TEXT. This is recorded.
  • Read repoctl help advisories for the codes and the recovery path.

Publish a fix while another node is not ready

A failed or unbuilt node makes its target not publishable. For an urgent fix, hold that node back for one publish: repoctl publish --hold NODE --reason TEXT. The reason has 8 characters or more. A held node keeps its old build.

You cannot hold a node that is current or staged. To publish only the targets that are ready, add --target TARGET. Read repoctl help urgent.

End a set

End an old set after its clients move to a newer set. The OCI packages and the branches stay.

  1. Move the clients to the release package of the next set.
  2. Add state: retired to each target in repoctl.yaml. Commit and push. Repository: the set branch. Build and publish now stop with set.retired.
  3. Remove the lines of the set from the mirror job on the HTTP server.
  4. On each admin host, run repoctl check --remove-timer, remove the worktrees and run repoctl clean --set NAME.

Read repoctl help end-set for the full text.

Housekeeping

  • Delete caches and old logs: repoctl clean --dry-run, then repoctl clean.
  • Delete old snapshots: repoctl repo gc, then again with --apply.
  • Check what the clients get: repoctl repo verify --served.
  • Upgrade repoctl: Install repoctl.
