Install repoctl

repoctl comes as signed RPMs from its own RPM repo. Install it on each admin host, check the host with repoctl doctor, and log in to the registry.

  • An admin host runs Fedora on x86_64. The targets are EL9 and EL10, built in mock chroots.
  • Check the key of the RPM repo by hand at the first install. dnf checks it after that.
  • The HTTP server needs only the package repoctl-mirror.
  • The notes of each GitHub Release give the sha256 and the key fingerprint for the checks.

Which host needs what

First install on an admin host

The RPM repo of repoctl is on GitHub Pages. You check its key at the first install, because dnf cannot check it yet.

  1. Download https://dennisklein.github.io/repoctl/rpm/repoctl-release-1-1.noarch.rpm.
  2. Compare its sha256 with the value in the notes of the newest GitHub Release.
  3. Install it: sudo dnf install ./repoctl-release-1-1.noarch.rpm.
  4. Run gpg --show-keys /etc/pki/rpm-gpg/RPM-GPG-KEY-repoctl. Compare the fingerprint with the tool repository key in the release notes.
  5. Install the tool: sudo dnf install repoctl.
$ repoctl version
$ repoctl doctor --only host

Check by hand, once

Do not skip steps 2 and 4. They are the only point where you, not dnf, decide to trust the key of the tool.

Prepare the host

Do these steps once on each admin host, in this order.

  1. Add your user to the group mock: sudo usermod -a -G mock $USER. Log out and log in again.
  2. Run repoctl doctor --only host. Fix each failed check. The hint of a check tells you the fix.
  3. Make a signing key, or use your key on a YubiKey (Signing key).
  4. Log in to the registry (Registry login).
  5. Run repoctl doctor inside a set directory. The groups sign and registry now pass.

A build needs free disk: 10 GiB in the data directory and in the cache directory, and 20 GiB in /var/lib/mock. repoctl doctor checks this, and a build stops early with exit 9 when the host is not ready.

Signing key

You sign each publish with your own key. Use a YubiKey for the key of a team member. repoctl help key gives the steps for the card. A file key is for a test set:

gpg --quick-gen-key "Your Name <you@example.org>" rsa4096 sign 3y
gpg --list-keys --with-fingerprint       # the fingerprint of the new key

Then tell repoctl which key is yours. Put one of these values in the user config ~/.config/repoctl/config.yaml:

Value of sign.keyExampleWhere it works
Full fingerprint (40 hex digits of gpg --list-secret-keys)F4EB…6792Everywhere. Use it on a new host.
User ID of the key, for example the mail addressd.klein@gsi.deEverywhere, when exactly one secret key in gpg matches it.
ID of the key in sign.keys of the setd.kleinOnly inside a set directory.
 
sign:
  key: d.klein@gsi.de

Run repoctl doctor --only sign. The check sign.key shows the key that repoctl uses.

A new key also needs repoctl sign add and a deployment record before it can publish. Keys and the team gives these steps.

Registry login

A publish pushes the snapshots to GHCR, and repoctl repo gc deletes old snapshots. Both need your token. A pull needs no token, because the packages are public. Log in once on each admin host, and again when the token expires.

Before you log in, decide where the token stays:

StoreUse it whenSteps
Auth file (plain text, ~/.config/containers/auth.json)You work over SSH, or the daily check of a set runs on this host.The steps below.
System keyring (Secret Service)You work in an open desktop session, and the token must not be on the disk in plain text.First steps 1 and 2 of Keep the token in the system keyring, then the steps below.
  1. Make a classic personal access token: open a new token with write:packages and delete:packages. Set the expiration to one year or less. Click Generate token and copy the token.
  2. Log in with podman. podman comes with repoctl. Type your GitHub login as the user name, and paste the token as the password: 
    $ podman login ghcr.io --authfile ~/.config/containers/auth.json
Username: dklein
Password:
Login Succeeded!
  3. Check the login: repoctl doctor --only registry. In any directory, it checks the login and the token of ghcr.io. 
    $ repoctl doctor --only registry
✓ registry.login: ghcr.io as dklein (container auth file)
✓ registry.scope: write:packages, delete:packages, expires 2027-11-09
    In a set directory, it also checks the packages of the set (registry.write, registry.public).

Use a token for the registry only

Do not use the token of gh auth or a fine-grained token. GHCR needs a classic token, and the token of gh has the scope repo. repoctl doctor warns about a scope other than the packages (registry.scope). Without delete:packages, all works but repo gc.

Why the option --authfile

The default file of podman is in /run/user. It is gone after a reboot, and the daily check of a set runs also when you are logged out. repoctl also reads ~/.docker/config.json, so oras login ghcr.io or docker login ghcr.io work too. To get oras, use for example mise use -g oras.

When a host is lost, delete its token on github.com/settings/tokens (host loss runbook).

Keep the token in the system keyring

The login above writes the token in plain text into auth.json. To keep it in the system keyring (Secret Service over D-Bus, the store of secret-tool), use a credential helper. podman writes the token through the helper, and repoctl reads it through the same helper.

  1. Install docker-credential-secretservice. Fedora and podman do not supply it. With mise: 
    mise use -g "github:docker/docker-credential-helpers[asset_pattern=docker-credential-secretservice-*.linux-amd64,bin=docker-credential-secretservice]"
docker-credential-secretservice version
    Without mise, get the release binary of docker/docker-credential-helpers. Check its sha256 with checksums.txt: 
    v=v0.9.12
f=docker-credential-secretservice-$v.linux-amd64
curl -fLO https://github.com/docker/docker-credential-helpers/releases/download/$v/$f
curl -fLO https://github.com/docker/docker-credential-helpers/releases/download/$v/checksums.txt
grep " \*$f\$" checksums.txt | sed 's/ \*/  /' | sha256sum -c
install -D -m 0755 $f ~/.local/bin/docker-credential-secretservice
    The directory ~/.local/bin must be in your PATH.
  2. Tell the auth file to use the helper for GHCR. If the file exists already, add the key credHelpers by hand. 
    mkdir -p ~/.config/containers
echo '{"credHelpers": {"ghcr.io": "secretservice"}}' >~/.config/containers/auth.json
  3. Log in as above: podman login ghcr.io --authfile ~/.config/containers/auth.json.
  4. Check that the keyring has the token: docker-credential-secretservice list shows ghcr.io. auth.json has no token.
  5. Run repoctl doctor --only registry.

The keyring must be open

repoctl asks the helper at each access to GHCR, also for a pull. This includes repo pull and the daily check of a set. A locked keyring stops the command, for example in an SSH session or in the timer of the check. Use the keyring only on a host with an open desktop session.

Shell completion

The RPM installs the completions for bash, zsh and fish. For another shell, run repoctl completion bash|zsh|fish|powershell. It writes the script to stdout.

The HTTP server

On the server that serves the repositories to the clients, run sudo dnf install repoctl-mirror. The mirror job pulls latest of each target, verifies the signatures, and swaps the served tree. You add one mirror line per target at the first publish of a set. The mirror job runbook has the details.

Upgrade

These steps are the text of repoctl help upgrade. A running build ends with the old binary, so wait for it.

  1. Read the release notes or the changelog. The section Upgrade names new keys, a new apiVersion and a new minRepoctl.
  2. Run repoctl runs --state running in each set. Wait until no run is active.
  3. Run repoctl ui --stop.
  4. Run sudo dnf upgrade repoctl repoctl-release.
  5. Run repoctl skills install. Add --project in each set that has skills.
  6. Run repoctl check --install-timer in each set with a timer.
  7. Restart each agent session that runs repoctl mcp start.
  8. Run repoctl doctor.

On the HTTP server, run sudo dnf upgrade repoctl-mirror. The design of the tool releases is in Tool releases.
